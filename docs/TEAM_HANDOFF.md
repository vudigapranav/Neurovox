# Team hand-off

For Pranav, Bhanuteja and Md. Ali: how to get the project running on your own laptop, how the work is split for
the viva, and how to collaborate without ever sharing anyone’s voice recordings.

## 1. Set up (each teammate, once)

1. Install **JDK 17 or newer** (e.g. Eclipse Temurin). Check: `java -version`.
2. Clone the repository. In the project folder:
   ```bash
   ./mvnw clean package          # Windows: mvnw.cmd clean package
   java -jar target/neurovox.jar
   ```
3. Open `http://localhost:8080`, follow **How to use**, and record one session yourself.
4. Optional, for the studies: Python 3.10+ and
   ```bash
   python3 -m venv .venv
   .venv/bin/pip install -r training/requirements.txt     # Windows: .venv\Scripts\pip install -r training\requirements.txt
   ```
   Node.js 20+ and Google Chrome for the browser check (README §6).

If anything fails, README §8 lists the common causes for macOS, Windows and Linux.

## 3. Collaborating without sharing recordings

Voice recordings are personal data. The rules:

- **Never commit** `data/`, `*.db`, `*.f32le`, `validation/recordings/` or any WAV of a real person. `.gitignore`
  already excludes them; check `git status` before every commit anyway.
- Everyone records into **their own** data folder. Share **numbers**, not audio: results are in the report, the
  history page and `sqlite3 data/neurovox.db`.
- For the Praat comparison on real voices, each person runs `validation/praat_compare.py` **on their own laptop**
  with their own WAVs in `validation/recordings/`, and shares only the generated `docs/results/praat_comparison.*`
  (they contain feature values and file names — name files neutrally, e.g. `p1-take1.wav`).
- Volunteers must agree before being recorded, be told the data stays on the recording laptop, and be able to have
  it deleted (History → Delete). Do not record anyone who is unwell to “test” the tool.
- For demos use a separate folder: `java -jar target/neurovox.jar --data-dir=demo-data`.
- Synthetic test audio (`validation/synthetic/`) is regenerated by a script and is safe to share, but is not
  committed because it is large; run `.venv/bin/python validation/make_synthetic_vowels.py`.

## 4. Working on the code

- Branch per change; run `./mvnw test` (and `node --test src/test/js/` if you touched the frontend) before pushing.
- Changing a formula? Update its Javadoc, bump `RecordingAnalyzer.EXTRACTOR_VERSION` (stored results of the old
  version are then not mixed in), rerun `validation/praat_compare.py`, and update VALIDATION.md with the new numbers.
- Retraining? Run `training/train_model.py`, then `./mvnw test` (the agreement test reads the new reference rows),
  and update VALIDATION §5 and PRESENTATION_INPUTS from `docs/results/model_evaluation.md`.
- The gate decision lives in `src/main/resources/model/research-gate.json`. Change it only as a team, with written
  evidence in VALIDATION.md.
